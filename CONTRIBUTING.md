# Contributing to HumanTone

Thank you for your interest in contributing to HumanTone.

HumanTone is an open-source collection of prompts, guidelines, and examples focused on helping AI-assisted writing better match a person's natural voice and communication style.

## How You Can Contribute

You can contribute by:

- Improving existing prompts
- Adding new prompts
- Adding useful writing examples
- Identifying common AI writing patterns
- Improving existing guidelines
- Fixing grammar or documentation issues
- Suggesting new ideas

## Before You Start

Please keep the main goal of the project in mind:

> Help writing sound natural and appropriate for the individual user and context.

Avoid creating rules that force everyone into one fixed definition of "human writing."

Different people write differently.

## Adding a New Prompt

If you add a new prompt:

- Keep the purpose clear.
- Explain when it should be used.
- Avoid unnecessary repetition.
- Make the instructions practical.
- Do not rely on one fixed writing style.
- Focus on adapting to the user's natural voice.

Place prompts inside the `prompts/` directory.

## Adding Examples

Examples should demonstrate a clear difference between generic and more natural writing.

When adding examples:

- Keep them realistic.
- Use context-appropriate language.
- Do not intentionally add random mistakes.
- Do not claim that one style is universally better.
- Explain the purpose of the example when necessary.

Place examples inside the `examples/` directory.

## Adding Guidelines

Guidelines should be practical and easy to understand.

When writing guidelines:

- Avoid unnecessary complexity.
- Use clear examples when helpful.
- Avoid absolute claims about AI detection.
- Remember that a single writing pattern does not prove something was written by AI.

Place guidelines inside the `guidelines/` directory.

## Writing Style

Keep contributions:

- Clear
- Direct
- Practical
- Easy to understand

Avoid unnecessary:

- Corporate language
- Filler
- Repetition
- Overly complex wording

Use headings and lists only when they improve readability.

## Pull Requests

Before submitting a pull request:

1. Check your changes for unnecessary repetition.
2. Make sure the file is placed in the correct directory.
3. Use a clear commit message.
4. Check that Markdown formatting works correctly.
5. Explain what your contribution adds or improves.

## Commit Messages

Use clear and simple commit messages.

Examples:

- Add short writing style prompt
- Improve social media examples
- Fix wording in writing principles
- Add common AI writing patterns

## Reporting Issues

If you find a problem or have a suggestion, open an issue with:

- A clear title
- A short explanation
- An example, if relevant
- A suggested improvement, if possible

## Code of Conduct

Be respectful.

Constructive feedback and different perspectives are welcome.

Do not attack contributors for their writing style, language ability, or level of experience.

## Final Note

The purpose of HumanTone is not to create one perfect writing style.

It is to help people preserve and communicate in their own voice.

Every useful contribution that supports this goal is welcome.
